# memo 引用采用「MEMO_LINK 升级」统一模型——评论 ≡ 引用（废弃缩进评论格式）

2026-09-05 P3 grill 定案。恢复「评论」时 owner 判定：个人记录场景的评论是伪需求，**引用系统才是通用能力**——新评论本质上是一条引用父 memo 的新 memo（独立卡片实体），渲染层面在被引用卡下方聚合、看起来像评论。因此废弃旧「缩进子树评论」数据格式与实体，评论按钮 = 快速创建引用卡。

**Status**: accepted（2026-09-05；取代 Era A 缩进评论与 Era B linkId 模型，见考古结论）

## 决策要点

1. **引用标记 = 升级 MEMO_LINK**，写在正文任意位置、一卡可多引用：`[@标签](日记文件名#^id)`——历史语法延续（1.0.0 起 `[@MEMO](memo.id)`），文件可读，无特殊头行记号
2. **引用目标 = 日记文件 + ^id**（迁移后全卡有持久 ^id）；不用内存 id（行号漂移会指错）、不用↗头行记号（正文不可读）、不用 Obsidian 原生块引用语法（与历史 MEMO_LINK 割裂）
3. **链式任意深**：引用卡可指向引用卡（回复评论 = 引用一条引用），渲染递归、展示限层
4. **聚合渲染**：被引用卡下可折叠聚合区（横条「N 引用」+角标，点击展开时间序）；识别 = content 匹配 MEMO_LINK 指向自己（历史 getLinkedMemos 同款，dev 规模无需索引）
5. **旧数据回填 = 迁移器 v2**：旧缩进评论行（4 空格 + `- ` + 14 位时间戳 + 内容）在正式库迁移时**直转引用卡**（14 位时间戳 = 真实日期；跨天评论落到评论当天日记 → 迁移引擎升级为跨文件操作）；同天评论原地转。已折叠数据拆不出（考古证实），dev 用 bak 原件重测
6. **孤儿策略**：父卡删除后引用卡独立存活，目标渲染为灰色「已删除」链

## Considered Options（被否）

- 评论独立实体/缩进子行：owner 判定伪需求；且 Era B 评论行只存 HH:mm:ss、跨日子夜错日（考古证实）
- ↗ 头行记号（ADR-0002 曾预留）：正文不可读、人看文件困惑
- Obsidian 原生块引用 `[[path#^id]]`：Obsidian 内原生可点，但与 MEMO_LINK 历史割裂、渲染聚合要另起炉灶
- 目标用内存 id（YYYYMMDDHHmmss+行号，MEMO_LINK 旧格式）：行号随编辑漂移，跨文件引用不可靠

## Consequences

- 模型不加引用字段：content 即真相，升级 MEMO_LINK 正则即可（getLinkedMemos/filter CONNECTED 自动生效）
- 文件重命名断引用链（接受，与 Obsidian 块引用同命运）
- 迁移器 v2 依赖本格式定案才能对正式库执行（v1 折叠为过渡行为，已迁的 dev 样本可弃用 bak 重测）
- 排序/时间显示：引用卡 = 普通卡（自己的时间/^id/软删/回收站语义全有）
