# memo 存储格式采用多行「卡片块」结构

2026-09-05 定稿。memo 落盘为卡片块：**头行 = `- [ ]? HH:mm:ss [deletedAt:…] ^6位id`（纯标识，行内无正文）+ 其后 ≥4 空格缩进的连续正文行**（可含空行/列表/代码块等块级 markdown）；块边界 = 缩进少于 4 的非空行、标题或文件尾。取代旧的「`- HH:mm:ss 正文… ^id` 单行 + 字面 `<br>` 编码」格式。

**Status**: accepted（2026-09-05 定稿；含 P1b 修订）

## Context

- 旧单行格式的正文不能有真换行，块级 markdown（列表/代码块/表格）全废；`<br>` 字面编码使文件不可读——是渲染器与输入框之外真正的瓶颈。
- 目标：memo 正文承载块级 markdown，文件观感借鉴 kanban（但评论不缩进）。

## 决策要点（完整解析规则见 PLAN-FORMAT.md 规格节）

- 头行纯标识：时间 `HH:mm:ss` 统一落盘（日期归文件名）；`^id` 恒 6 位（Obsidian 原生维护）；`deletedAt` 软删标记放头行 `^id` 前、无方括号。
- 正文缩进 4 空格（CommonMark 兼容）；空行分段、额外缩进给嵌套。
- 任务态 = 头行 `- [ ] 12:00:00 ^id`（勾选写回头行，渲染为时间旁勾选框）。
- 评论/引用：本期停摆（缩进子树 + linkId 语义作废，模型字段备用），P3 引用卡重建。

## 读取策略的演变（决策曾被修订）

1. 初版：文件级探测（首条 memo 是否纯标识头）→ 双模式解析。
2. **P1b 修订（2026-09-05 owner 拍板）**：改为**行级判定**（`classifyMemoRow` 三态）——旧顶层行不渲染、不进回收站，统一交数据体检「整文件迁移」恢复；写入只写新格式，新旧混合文件合法。

## Consequences

- 旧数据不渲染、写入只写新格式；恢复手段 = 体检「整文件迁移」（自动备份到 `.rememo-backup/`）。
- 读取不再隐式改写文件：缺 id 只内存兜底，落盘修复归体检 missing-id 规则。
- 行级解析语义单一来源：`src/helpers/memoLine.ts`（读端/规则/迁移共用，禁止别处再抄正则）。
- 处理区（ProcessEntriesBelow 语义）：`''` 时从文件头到首个 `# ` 标题止，读取/体检/迁移三处同款。
- 完整格式样例与解析规则、体检引擎架构：PLAN-FORMAT.md（本文件不重复）。
